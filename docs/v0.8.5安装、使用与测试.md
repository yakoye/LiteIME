# PiInput v0.8.5 安装、使用与测试

## 安装

完整解压 `PiInput-v0.8.5-windows-x64.zip`，运行根目录 `PiInput-Install.exe`。

安装器有界面：先显示确认页，说明装到哪两个位置、本次是全新安装还是覆盖升级、为什么需要一次管理员权限；安装过程走进度条；完成页把「打开设置程序和配置目录」改成可勾选项。用户文件和设置仍安装在当前普通用户目录。

已装过旧版时**不需要先卸载**，直接运行安装器即可覆盖升级，用户词库、设置和学习记录都会保留。

## 如果 Windows 拦下了安装器

PiInput 目前**没有代码签名证书**，因此在开启了防护的机器上会被拦。这不是程序有问题，是 Windows 无法验证发布者。

**智能应用控制（Smart App Control）** 会显示「已阻止可能不安全的应用……因为无法验证其发布者」，并且只给「正常」和「从 Microsoft Store 获得应用」两个按钮 —— 它在强制模式下**不提供绕过入口**，这一点和 SmartScreen 不同。唯一的办法是关闭它：

> 设置 → 隐私和安全性 → Windows 安全中心 → 应用和浏览器控制 → 智能应用控制 → 关闭

**注意这个操作是单向的**：智能应用控制一旦关闭，除非重装系统否则无法重新开启。请自行权衡是否值得。

**注意「正常」按钮不是放行。** 它相当于「确定」，作用只是关掉弹窗，应用依旧不会运行 —— 这一点常被误解为程序本身有问题。改名、换目录、用命令行启动都无效，已实测。

被拦的只有安装器一个文件：同一个包里的其他程序、以及安装后的 `PiInputTSF.dll` 都能正常运行。原因是安装器具备提权、写系统目录、注册 COM 这组特征，判定门槛更高，而每个新版本对系统而言都是没见过的新文件。因此**旧版本能装不代表新版本能装**。

**Microsoft Defender SmartScreen** 是另一回事，它的拦截可以绕过：在「Windows 已保护你的电脑」弹窗上点「更多信息」→「仍要运行」。关闭智能应用控制之后如果还遇到弹窗，多半是这一个，走这条路即可。

两者的区别：

| | SmartScreen | 智能应用控制 |
| --- | --- | --- |
| 弹窗标题 | Windows 已保护你的电脑 | 已阻止可能不安全的应用 |
| 是否可绕过 | 可以，「仍要运行」 | **不可以**，强制模式下无放行入口 |

查看某个机器的智能应用控制状态：

```powershell
(Get-ItemProperty "HKLM:\SYSTEM\CurrentControlSet\Control\CI\Policy" -Name VerifiedAndReputablePolicyState).VerifiedAndReputablePolicyState
```

`0` 是关闭，`1` 是强制，`2` 是评估模式。

签名是转入正式版的门禁之一，尚未完成；在此之前分发给他人都会遇到这个问题。

## 本版改动：句号的形态由「这次会提交什么」决定

上一版（v0.8.4）把句号的两键规则从「只认数字」扩到「字母数字」，但**只对已经上屏的字母生效**。打 `geek` 的时候它还是个未上屏的合成串，走的是另一条路——有合成串时句号直接取中文形式，规则被跳过。所以对最常见的用法，上一版等于没改。

现在判据改成「**这次按下去会提交什么文本**」：

| 输入 | 提交的文本 | 第一次按 `。` | 再按一次 |
| --- | --- | --- | --- |
| `nihao` 选「你好」 | `你好` | `你好。` | —— |
| `geek`（无候选，原样上屏） | `geek` | `geek.` | `geek.。` |
| `0.8` | `0.8` | `0.8.` | `0.8.。` |

**中文输入完全不受影响**——拼音上屏为中文时，句号仍是第一次就给 `。`。冒号同理。

上一版的另外两条修复继续有效：横杠可输入（`apple-book`），以及已上屏字母后的句号规则。

## 本版必测项

1. **中文输入不受影响**（最重要）：打 `wo` 选「我」再按句号，应直接得 `我。`；打一段完整中文确认句号行为与以往一致。
2. **无候选的拉丁输入**：打 `geek` 再按句号得 `geek.`，再按一次得 `geek.。`。
3. **数字后的句号**：打 `0.8.1`，应逐字符如实输出。
4. **已上屏文本后的句号**：先上屏一个英文词，再单独按句号得 `.`，再按一次得 `。`。
5. **中文文本后的句号**：已上屏的中文后按句号，直接得 `。`。
6. **冒号同理**：`http` 后第一次得 `:`；`注意` 后直接得 `：`。
7. **横杠可输入**：中文模式打 `apple-book`，横杠应正常落下。
8. **翻页未被破坏**：出候选后按 `=` 展开，再按 `-` 应往回翻一行。
9. **升级不中断已开程序**：装上本版后**不重启**任何已打开的程序，在其中继续打字，应正常工作。
10. **重启后文件仍在**（v0.7.16 的核心修复）：升级安装后重启电脑，运行 `piinput-diagnostics.exe`，`shim_exists`、`host_exists`、`lexicon_exists` 必须全部为 `true`。

**注意：每个受测程序都要重启。** 输入法组件是 DLL，程序不重启就还是旧版本，改动不会生效。

## 已知限制

**终端里候选框不跟随光标。** MobaXterm 这类程序不向系统报告插入点位置——它维护的不是文本文档而是自己绘制的字符网格，`GetTextExt`、`GetScreenExt` 和系统光标三条路都问不出结果（实测均返回固定的退化值）。目前做到的是稳定、不乱跳、落在输入区附近，做不到跟随。普通编辑器和浏览器不受此限制。

**有些程序会主动禁用输入法。** 例如 YeImageViewer 调用了 `ImmDisableIME`，那之后 Windows 不会把任何输入法加载进该进程——搜狗、微信输入法、小狼毫、PiInput、乃至语音输入全部失效。这不是输入法能绕开的，需要那个程序自己改。

## 核心检查

1. 在记事本、Notepad++、Chrome 和 Windows 搜索分别输入 `zhongwen`，确认组合、候选和空格上屏。
2. 输入数字 `123`，不得丢失首个数字；远程桌面地址框等数字输入框应直接透传。
3. 中文组合输入 `cmd` 后单按 Shift，应上屏 `cmd` 并切到英文。
4. 中文标点下验证 `1.文本`、`1..`、`12:23`、`2/3` 和中文冒号、分号。
5. 在快捷表中新增一个图标行，保存并重新打开设置，确认五个字段和行数不丢失。

## 工具入口

- `fh/bq/sz`：候选 2 分别打开符号、表情和设置。
- `jsq`：候选 2 打开 Windows 计算器，候选 3 打开随包程序员计算器。
- `msp`：候选 2 打开 Windows 画图。

## 诊断

排查候选问题时，可在临时目录放置 marker 文件开启日志，默认全部关闭：

| Marker | 日志 | 用途 |
| --- | --- | --- |
| `piinput-candidate-trace.on` | `piinput-candidate.log` | 宿主是否接管候选显示 |
| `piinput-caret-trace.on` | `piinput-caret-trace.csv` | 候选窗定位与实际落点 |
| `piinput-langbar-trace.on` | `piinput-langbar.log` | 语言栏按钮注册 |
| `piinput-key-trace.on` | `piinput-key-trace-<pid>.csv` | 每个按键的去向：应用交没交出来、有没有派发、候选框定位取自哪个来源 |

按键追踪只记录「这个键发生了什么」，不记录输入的文本内容。它是本版三条修复的取证手段：`key_offered` 记应用交出过哪些键及决定，`key_down` 记实际送达，两者不匹配即为应用丢键；`key_down_recovered` 记补做，在行为正常的程序里应恒为 0。

排查完成后删除 marker 文件，避免持续写日志。

## 版本确认

```powershell
& "$env:LOCALAPPDATA\PiInput\bin\PiInputHost.exe" --version
& "$env:LOCALAPPDATA\PiInput\bin\PiInputHost.exe" --build-id
```

输出应分别为 `0.8.5` 和验证文档记录的精确 `0.8.5+<commit>`。

## 卸载

从 Windows「已安装的应用」卸载 PiInput，或运行包根目录 `PiInput-Uninstall.exe`。卸载默认保留 UserData。
