# 三个长文本打字测试（v0.8.4）

v0.8.4 继续执行三组真实文本逐键回放、段落输入、结构化语料和逐键延迟门禁。

本版改的是标点判定，**语料里的句号行为会变**，这是预期之中的：以拉丁字母结尾的位置，第一个句号现在是 ASCII 而不是中文。回放结果与 v0.8.3 的差异应当**只出现在这类位置**，其余逐字节一致。

## 本版必须复验的项

- **中文行文的句号逐字节不变。** 中文字符的最后一个字节不是 ASCII，两键规则碰不到它。语料里绝大多数句号属于这一类，出现任何差异都说明判定写错了。
- **差异只出现在字母/数字之后。** 逐条核对回放输出与 v0.8.3 的差异位置，每一处的前一个字符都应当是 ASCII 字母或数字。
- **延迟门禁未退化。** 本版没有在按键路径上增加工作量，判定只是把一个字符分类函数换成了另一个。
- **候选翻页未被破坏。** 结构化语料里若有展开候选后翻页的用例，行为应与 v0.8.3 一致。

## 真实应用手工测试

必须使用验证记录中的同一 build ID。**每个受测程序都要重启**——输入法组件是 DLL。

1. **横杠可输入**：中文模式打 `apple-book`，横杠应正常落下；`in-to` 同样确认。
2. **英文模式下的横杠**：切到英文模式打 `apple-book`，同样正常。
3. **翻页未被破坏**：打一段拼音出候选，按 `=` 展开，再按 `-` 应往回翻一行；翻到顶再按一次应收回单行。
4. **字母后的句号**：打 `apple` 再按句号得 `.`，再按一次得 `。`。
5. **数字后的句号**：打 `0.8.1`，应逐字符如实输出（这是 v0.8.2 起就有的行为，本版不得破坏）。
6. **中文后的句号**：打一句中文再按句号，应直接得 `。`。
7. **冒号同理**：`http` 后第一次按冒号得 `:`；`注意` 后按冒号直接得 `：`。
