## 自动验证

- 干净 Release 构建，全量 CTest 通过（68 项）。
- 新增 `host_session` 层测试，走的正是实际路径：`wo` + 句号得 `我。`，`qqq` + 句号得 `qqq.`。

## 最重要的一条断言

`wo` + 句号必须得 `我。`。

这条不是锦上添花，它是这次改动的**边界**：为了让 `geek.` 成立而误伤正常中文输入，是比原问题严重得多的回退。合成串里装的是原始拼音（`composition_text = source.input`），`nihao` 的最后一个字节是字母——任何直接拿合成串文本去判的写法都会让 `你好。` 变成要按两次。这条测试就是防这个。

## 实机验证

由用户在真实程序中确认：

- `geek` + 句号得 `geek.`，再按一次得 `geek.。`。
- `wo` 选「我」+ 句号直接得 `我。`。
- `apple-book` 的横杠正常（v0.8.4 的修复未被破坏）。

## 已确认的行为

- **符号的形态由它跟在什么后面决定，而合成串上屏时那是「本次提交的文本」。** 该文本只有 Host 知道：可能是选中的候选，也可能是原样上屏的输入。输入法组件在按键送出之前无法得知，它手上只有原始拼音。
- **规则只有一份定义。** 判据抽成公开静态，两处调用它而输入不同——一处问文档，一处问提交。此前把规则复制到两处会各自漂移。
- **v0.8.4 的修复本身没有问题，只是覆盖面不够。** 它解决的是「字母已经上屏」的情形，那条路径依然有效且有测试覆盖。
