# PiInput v0.8.5 版本说明

本版只修一件事：v0.8.4 那条句号规则没修到最常见的那个场景。

## `geek。` 仍然是中文句号

v0.8.4 把两键规则从「只认数字」扩到「字母数字」，但**只对已经上屏的字母生效**。

你打 `geek` 的时候它还是个未上屏的合成串，而判定的入口一开头就有一条：**有合成串时句号直接取中文形式**，下面所有规则——包括刚扩展的那条——全部跳过。所以对最常见的用法，v0.8.4 等于没改。

## 为什么不能简单去掉那条早退

合成串里装的是**原始拼音**。`nihao` 的最后一个字节是 `o`，拿它去判的话，`你好。` 就会变成要按两次句号——这是比原问题严重得多的回退。

## 真正的判据

符号跟在什么后面，取决于**这次按下去会提交什么文本**：

| 输入 | 提交的文本 | 句号 |
| --- | --- | --- |
| `nihao` | `你好` | `。` |
| `geek` | `geek` | `.` |

而这个信息**只有后台进程知道**——输入法组件在按键送出之前就要决定，那时合成串还没上屏。所以这一步的判定移到了后台：有候选就看候选文本，没候选就看原样上屏的输入。

规则本身仍然只有一份定义，两边共用同一个判据函数：输入法组件问的是「文档里光标前面是什么」，后台问的是「这次会提交什么」。没有合成串时前置文本为空，规则不成立，原来的判定原样通过。

## 行为一览

| 输入 | 第一次按 `。` | 再按一次 |
| --- | --- | --- |
| `geek` | `geek.` | `geek.。` |
| `0.8` | `0.8.` | `0.8.。` |
| `nihao` 选「你好」 | `你好。` | —— |
| 已上屏的中文 | `。` | —— |

冒号同理。
